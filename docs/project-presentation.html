Introduction

What Is This Project?

An automated test suite that opens a real browser and tests every feature of saucedemo.com — login, product browsing, cart, checkout — without any manual effort.

The Problem

Manual testing is slow, repetitive, and error-prone. A human can't click through 46 test scenarios every time code changes.

The Solution

Write code that acts like a user — clicks buttons, fills forms, checks results — and runs all 46 tests in minutes.

Architecture

Page Object Model (POM)

Each page of the website gets its own Java class that stores locators (how to find elements) and methods (actions on that page).

Without POM

Button ID changes? Fix it in every test file that uses it. 20 tests = 20 fixes.

With POM

Button ID changes? Fix it in ONE page class. All 20 tests automatically use the fix.

Pages: LoginPage, ProductsPage, CartPage, CheckoutStepOnePage, CheckoutStepTwoPage, CheckoutCompletePage, ProductDetailPage, SidebarMenu

Synchronization

Wait Strategy: No Thread.sleep

Bad: Thread.sleep(3000)

Always waits 3 seconds, even if the element appears instantly. Slow and unreliable.

Good: Explicit Waits

Checks every 500ms. Moves on immediately when ready. Fails after 10s timeout if element never appears.

All waits go through WaitUtils.java which wraps WebDriverWait:

  • waitForVisible() — Wait until element is visible
  • waitForClickable() — Wait until element can be clicked
  • waitForInvisible() — Wait until element disappears

Reporting

Dual Reporting System

Extent Reports

Standalone HTML file at reports/ExtentReport.html. Shows pass/fail, failure screenshots, and test details. Generated automatically.

Allure Reports

Interactive dashboard via mvn allure:serve. Tests organized by Epic/Feature/Severity. Step-by-step logs. Timeline view.

On failure: Screenshot is auto-captured and attached to both reports. The URL where the failure occurred is also logged.
